

🚀 Statement vs PreparedStatement (Interview Table)


| Feature       | Statement                                                                      | PreparedStatement                                                                    |
| ------------- | ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------ |
| Meaning       | “Statement is used to execute simple SQL queries directly without parameters.” | “PreparedStatement is used to execute parameterized SQL queries using placeholders.” |
| Query Type    | “We write full SQL query every time with values inside it.”                    | “We write query once with `?` and reuse it by passing values.”                       |
| Security      | “It is less secure and can be vulnerable to SQL Injection.”                    | “It is more secure because it separates data from query.”                            |
| Performance   | “It is slower because query is compiled every time.”                           | “It is faster because query is compiled once and reused.”                            |
| Data Handling | “It does not support dynamic values properly.”                                 | “It easily handles dynamic values using setter methods like setInt, setString.”      |


“Statement is used to execute simple SQL queries directly,
 but it is not secure and can lead to SQL injection. 
 PreparedStatement is a better version where we use 
 placeholders and pass values separately. 
 It is more secure because it prevents SQL injection,
  and it is also faster because the query is compiled only
   once and reused multiple times. That’s why in 
real projects we prefer PreparedStatement over Statement.”

--------------------------------------------
“Important methods of Connection object are createStatement() 
for simple queries, prepareStatement() 
for secure parameterized queries, close()
 to release connection, and transaction methods like
  setAutoCommit, commit, and rollback for managing database
   transactions. These are 
essential for proper JDBC usage in real applications.”

🚀 1. prepareStatement():
Used to create a PreparedStatement object for executing parameterized SQL queries.

🚀 2. createStatement():
Used to create a Statement object to execute simple SQL queries directly.

🚀 3. close():
Closes the database connection.
Frees database resources
Prevents memory leaks
Very important in real applications

🚀 4. setAutoCommit(false)
con.setAutoCommit(false);
Stops automatic saving of changes in database.

🚀 5. commit()
con.commit();
Saves all changes permanently to database.

🚀 6. rollback()
con.rollback();
Cancels all changes if something goes wrong.

# 🚀 JDBC Execution Flow (End-to-End Understanding)

When we run a JDBC program, everything happens in this sequence:

```text id="f1"
1. Load Driver
2. Create Connection
3. Create Statement / PreparedStatement
4. Execute Query
5. Store Result (if SELECT)
6. Process ResultSet
7. Close Connection
```

---

# 🔥 Step-by-Step Explanation

---

## 1. Load Driver

```java id="f2"
Class.forName("com.mysql.cj.jdbc.Driver");
```

### What happens?

* Java loads MySQL driver
* It acts like a bridge between Java and Database

---

## 2. Create Connection (con)

```java id="f3"
Connection con =
DriverManager.getConnection(url, user, pass);
```

### What happens?

* Java connects to database
* This is like opening a “door” to DB

👉 Without this, nothing works

---

## 3. Create Statement / PreparedStatement

### Option 1: Statement

```java id="f4"
Statement st = con.createStatement();
```

### Option 2: PreparedStatement

```java id="f5"
PreparedStatement ps = con.prepareStatement(query);
```

### What happens?

* You prepare SQL query execution tool

---

## 4. Execute Query

### If SELECT:

```java id="f6"
ResultSet rs = st.executeQuery();
```

or

```java id="f7"
ResultSet rs = ps.executeQuery();
```

### If INSERT / UPDATE / DELETE:

```java id="f8"
int rows = ps.executeUpdate();
```

---

## 5. What is difference here?

| Query Type           | Method Used     | Output          |
| -------------------- | --------------- | --------------- |
| SELECT               | executeQuery()  | ResultSet       |
| INSERT/UPDATE/DELETE | executeUpdate() | int (row count) |

---

## 6. ResultSet (only for SELECT)

```java id="f9"
while(rs.next()) {
   System.out.println(rs.getInt("id"));
}
```

### What happens?

* Moves row by row
* Reads data from database response

---

## 7. Close Connection

```java id="f10"
con.close();
```

### Why?

* Frees database memory
* Releases connection

---

# 🚀 FULL SIMPLE FLOW (MEMORIZE THIS)

```text id="f11"
Java Program
   ↓
Driver loads
   ↓
Connection created (con)
   ↓
Statement / PreparedStatement created
   ↓
Query executed
   ↓
If SELECT → ResultSet
If INSERT/UPDATE/DELETE → int
   ↓
Process output
   ↓
Close connection
```

# 🔥 Real-Life Analogy (Very Easy)

Think like:

| JDBC Part         | Real Life         |
| ----------------- | ----------------- |
| Driver            | Translator        |
| Connection        | Phone call to DB  |
| Statement         | Asking question   |
| PreparedStatement | Safe form filling |
| executeQuery      | Asking for data   |
| executeUpdate     | Changing data     |
| ResultSet         | Answer sheet      |

---

# 🎤 Interview Ready Answer (VERY IMPORTANT)

> “JDBC execution starts by loading the driver, then establishing a connection with the database. After that, we create Statement or PreparedStatement to execute SQL queries. For SELECT queries, executeQuery returns a ResultSet which stores data row by row. For INSERT, UPDATE, DELETE we use executeUpdate which returns number of affected rows. Finally, we close the connection to release resources.”

